## 驗證順序與門檻

1. **短 smoke（P0，<30min）**：真 PAM 音檔、重跑差 ≤1e-4、strict checkpoint keys、SAE shape4096、finite output；與官方 `_extract_batch` batch1 + 官方 dataset padding／CNN 對照。只測程式，不看人工評分。
2. **外部 PAM 主效度**：固定 400 首生成音樂（4系統×100 prompt），同一 released 5秒與既有 PAM OVL，AES PQ/CE 沿用該片段的 per-clip 分數。100首 real 另外描述，不混入生成主終點。PAM 不在 MEva 論文的五個監督 benchmark；不以訓練內 MusicEval 的相關性宣稱外部泛化。
3. **主終點**：生成400首 MEva vs OVL Spearman，與 PQ、CE 的配對差；prompt cluster bootstrap 2000次、seed20261003。兩個差用97.5%區間（Bonferroni，同時95%coverage）。Pearson、同prompt配對一致率為次要。模型不再fit；報整體與系統內結果，避免只靠系統差異製造漂亮r。
4. **外部 gate（研究建議，非論文門檻）**：相對 PQ、CE，rho 差的 simultaneous CI 下界都>0，點估計都≥0.05，MEva rho CI 下界≥0.60。是否過門檻都繼續已授權的歷史 **shadow** 重評，方便查看排序差異；失敗不能宣稱能取代 AES。
5. **PromptCC 重評**：只納入本機 retained MF25 cells 且來源 passed report、完整 per-clip TSV與音檔皆存在。精確 coverage 在 runtime/coverage.json。保留 CFG0、CFG3 fidelity8 及其他歷史 protocol 的獨立標籤；僅有真正 CFG3 fidelity8 canonical資料才作 canonical comparison。不把高MEva分數本身當真人效度證據。
6. **採用 gate**：外部成功仍需 PromptCC 新真人盲評；固定 prompt、同候選池、同K、比較AES與MEva選top1，prompt cluster CI勝率下界>0.5、CLAP與缺陷無預定退步後才能改生成排序。將來盲評600支×5人是預算起點，正式樣本數需pilot power analysis後另立 immutable contract。
