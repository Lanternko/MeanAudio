# TTM 音樂生成與品質指標比較：表格草稿及實驗規劃

日期：2026-10-07（Asia/Taipei）  
狀態：研究草稿，已經過一輪設計審閱（審閱者：Claude，2026-10-07，見第 9 節）；不是已批准的實驗合約或可執行佇列。  
授權範圍：整理規劃。本文未啟動生成、評分、聽測或長時間運行，未變更現有實驗合約、結果和佇列。  
術語：TTM = text-to-music。

## 0. 審閱修訂摘要（2026-10-07）

第一版的程序性公平規則（同文本、K=1、同評分器、盲聽、invalid gate）保留。審閱發現四個**結構性偏誤**：條件全部對齊後，評分器或協議本身仍偏向某一方，第 7.3 節的 invalid gate 抓不到。本版修正如下：

1. **MeanAudio 的 canonical 協議是在評估集上以評估指標調出來的。** fidelity8 負向 prompt 在 MusicCaps 上以 AES PQ 為目標選出，約 +0.8～1.0 PQ，同時 FAD 變差（negprompt 消融、105、084）。外部模型沒有同等調參。→ 主表加入 MeanAudio CFG0 列；外部模型一律用官方預設值，不另調參；MusicLDM 另加一列同 fidelity8 負向的對照（第 7.5 節）。
2. **AES PQ 已知會被 PQ 導向方法 game。** 081（PQ 標籤前綴）勝過 87% 真實錄音、FAD 未過；084 是 PQ 導向的蒸餾。→ 這類 checkpoint 的 AES 欄不進跨系統排名（第 7.6 節）。
3. **MEva 以 MusicGen-small 的內部表示作為特徵**（`docs/metrics/meva.md` 第 5 步）。→ 對 MusicGen 系列的輸出，MEva 是共用骨幹的評分，不進跨系統排名；MusicEval 系統名單需核驗是否含 MusicGen／MusicLDM（第 7.6 節）。
4. **AES 會高估 16 kHz 擴散系統**（PAM：audioldm2 +1.46），而且頻寬 probe 顯示低通 8 kHz 幾乎不改變 AES，所以共同頻寬處理**不能消除**這個偏誤。→ MeanAudio／MusicLDM（16 kHz）對 MusicGen（32 kHz）的 AES 比較只作描述，跨系統優劣以人評為準（第 7.6 節）。

另外修正：白噪音 SNR 階梯改在共同取樣率下加噪（不同取樣率下同 SNR 的頻帶能量不同）；pilot prompt 排除在正式聽測集外；聽者不得是熟悉 MeanAudio 輸出的實驗室成員，並加盲度檢查。

## 1. 目標和研究問題

最終交付一張可用於彙報的 TTM 大表格，並附上支持它的資料清單、指標效度表、劣化測試表、人類聽測表及獨立的分數分佈圖。

研究問題：

1. 在相同文本和評價條件下，MeanAudio、MusicGen、MusicLDM 各有哪些優勢？
2. AES 與固定版本的 MEva，在不同資料來源、品質範圍和系統內比較中，能否預測人類判斷？
3. 對同一音檔加入噪音等劣化後，指標是否有反應？SNR 30 dB 的變化是否聽得出來、是否影響品質偏好？
4. 各模型與真實錄音的分數分佈有何差異，包括集中程度、低分尾部和高分飽和？

「AES 擅長辨識明顯劣質樣本，MEva 擅長區分高品質樣本」是待檢驗假說，不能只憑分佈圖或單一相關係數認定成立。

公平性是進入正式比較的必要條件：同一測試內，所有候選共用評價標準和實驗背景，只允許預登記的待檢驗因素不同。程序對齊之後，還必須確認**評分器與協議本身沒有已知偏向某個候選**（第 7.6 節）。不同任務可以有各自的協議，但不能跨協議合併排名或宣稱勝負。

表 B 報告約定：

- 逐曲指標列出平均值及 95% CI；中位數、標準差、P10／P90 放附件。n 是該指標實際有效的樣本數，不能預設各欄相同。
- FAD 是集合層級指標。鎖定 embedding 模型、權重、層、取樣率、參考集合（`/mnt/HDD/kojiek/musiccaps_reference`，必須明確傳入）、樣本數和軟體版本；不能畫成逐曲分數分佈。真實集合對自身算出的 FAD 不作為比較成績。
- 生成系統之間的總體優劣以預先指定的人類主要終點為準；CLAP、FAD、PQ、CE 各自回答不同問題，不預設相加成綜合總分。
- **跨系統排名欄位的資格**：只有沒有被第 7.6 節標記的評分器／候選組合才能放進排名敘述。帶 †‡§ 的格子照樣報數字，但只作描述。
- MEva 在本計畫中維持 shadow 指標；高分或域內高相關，不會自動讓它取代 AES。
- CU、PC 是內容適用性／製作複雜度的預測軸，不能預設「越高越好」，也不等於技術品質。
- 人類結果明確標記子集 n 和標註次數，不能寫成對全部 5,521 首都做過聽測。
- 聽測使用原生頻寬並統一響度，回答的是實際輸出的品質；共同頻寬版本另作次要分析，不能把升取樣解釋成恢復高頻。

品質範圍測試：

- 依獨立的人類評分或盲聽缺陷標籤分層，不用 AES／MEva 自己的分數定義「高品質」。
- 不同的人類量尺不能共用同一個絕對閾值。先在各資料集用原始量尺登記閾值；分位數分層只作次要敏感度分析，並公布邊界。
- 跨系統和系統內結果分別報告。高品質層的範圍縮窄會讓相關係數下降，所以要同時報告人類差距、成對一致率及人類一致性，不能只看相關下降。
- 檢驗「精挑細選」時，另按人類差距小／中／大分組；小差距層如果人類自己都無法穩定判斷（PAM：差 < 0.5 時一致率 0.46），結論應為證據不足。
- 校準誤差只用於同目標、同量尺的分數，或用獨立校準集擬合並凍結映射。MEva 與人類 PQ 的原始差值不能直接當作誤差。
- 新實驗不調整評估器權重。若未來需要重新訓練或校準，須另立合約，並依文本、來源隔離訓練／驗證／測試集。

操作與解讀：

- **加噪前先把所有來源統一到 16 kHz**（重採樣演算法登記並固定）。在 32 kHz 下加白噪音，同 SNR 會有一半能量落在 8–16 kHz，16 kHz 來源沒有這段頻帶，跨來源的 Δ 就不可比。原生取樣率的加噪版本若要做，另成 block。
- 固定原版音檔和噪音種子，登記 SNR 的能量計算窗口、聲道規則和靜音處理。可用純增益縮放避免越界；不能用未登記的 limiter 消除削波。
- 每個基礎音檔生成完整的條件階梯；同一基礎音檔使用同一條單位功率噪音序列，只按 SNR 縮放，避免噪音的隨機實現不同而混淆 SNR 效果。
- 驗證派生音檔的實測 SNR、數值有限性和峰值；近靜音樣本按預定規則標為無效，不臨時換成效果明顯的樣本。
- 原始版本與響度控制版本分別分析。響度控制規則同第 7.7 節（−30 LUFS、純量增益、不用 limiter）。
- 「聽得出不同」與「比較喜歡原版」是兩個終點。SNR 30 的可辨識性用盲測 ABX，偏好用 A/B 並允許平手。
- 對同一來源音檔做配對統計；派生條件不能當作獨立樣本擴充 n。
- 指標敏感度與真實模型排序效度分別下結論；能辨識噪音不代表能區分兩首乾淨的音樂。

聽測隱藏系統名和指標分數，隨機左右順序，固定播放處理並記錄設備要求。技術品質、整體喜好和文本符合度分開提問，避免把「乾淨」「好聽」「符合描述」混成一題。登記聽者篩選、重複題、品質檢查及排除規則。

同一測試採用同一份問卷、評分錨點、文本呈現方式、耳機／環境要求、校準程序和有效聽者數。聽者採隨機平衡分配，不能讓某個模型只由另一類聽者評價。統一響度使用同一演算法與目標，並凍結峰值越界的處置；聽者不得看到系統名，也不能有候選專屬的播放增益調整。

盲度：

- **聽者不得是熟悉 MeanAudio 輸出的實驗室成員**（包括本專案作者）。MusicGen 的音色很好辨認，熟悉的聽者等於沒有盲測。
- 每位聽者在測驗結束後，對一小組預先固定的 trial 回答「你認為這段是哪個系統」。猜中率顯著高於機率時，在報告中標記該比較的盲度不足。
- P1 pilot 使用的 prompt **排除在正式聽測子集之外**；pilot 的標籤也不進入確認性分析。

## 3. 獨立交付：分數分佈圖

本項對應會議中的「波峰圖」，正式名稱為分數頻數直方圖。它屬於描述分析，不能單獨證明指標準確或模型較好。

- 橫軸：指標預測分數；AES PQ 為首圖，CE／CU／PC、MEva 各自成圖。
- 縱軸第一版：每個分數區間的音檔數量。
- 縱軸第二版：該區間數量 ÷ 此條件的有效音檔總數，方便比較 5,521、400、2,748 等不同樣本量。
- AES 主圖使用 0.1 分固定區間；例如標為 7.6 的柱代表 [7.6, 7.7)，不是原始浮點數恰好等於 7.6。另提供 0.2 分寬的敏感度版本。
- 不同組的同一指標使用相同區間邊界及座標。MEva 保留自身量尺，區間邊界在作圖前依已核驗的官方量尺凍結；不與 AES 共用 1–10 橫軸。
- 不截掉超出顯示範圍的有效預測值，保留上下溢出計數。末區間端點、浮點邊界規則、NaN／缺失處理都寫進作圖設定。
- 每張圖標明模型／資料來源、協議、raw 或響度控制、有效 n 和缺失 n。依資料集分面，避免多個來源混合產生的多峰被誤認為同一模型的現象。帶 †‡§ 的組合在圖上同樣標記。
- 附平均值、中位數、P10／P90，並匯出 bin_left、bin_right、count、proportion 的 CSV。所有柱的數量總和必須等於有效 n。
- 平滑密度曲線可選，只作輔助，避免平滑造出不存在的波峰。CLAP 可單獨畫分佈，FAD 沒有逐曲直方圖。

## 4. 指標選擇與版本鎖定

| 指標 | 角色 | 必須鎖定 | 使用邊界 |
|---|---|---|---|
| 人類技術品質／整體喜好 | 感知比較的依據；跨系統優劣的主要終點 | 問卷、量尺、抽樣、播放條件、聽者規則 | 子集覆蓋與不確定性必須公開 |

| 學習式 MOS 預測器（類別） | 本表的 AES 與 MEva 就是這一類：用人評訓練的神經網路評分器。語音領域自 2019 年（MOSNet 起）把它當評估的一環，音樂領域近兩年跟上（AES 2025、MusicEval 2025、SongEval 2025） | 每個成員各自鎖定版本與權重 | 一律報它對人評的效度（表 C）以及對候選的已知偏誤（第 7.6 節）；不另加語音域的 MOSNet／DNSMOS 欄位，因為未經音樂效度驗證 |
| MIR 節奏／調性特徵 | 後續可選補充 | 現有實作、特徵清單與分析方案 | 不擴大第一輪主表的範圍 |

官方 AES 實作提供 CE、CU、PC、PQ 四軸及逐檔輸出，見 [Audiobox Aesthetics](https://github.com/facebookresearch/audiobox-aesthetics)。外部 MusicGen 的版本與生成控制以 [AudioCraft](https://github.com/facebookresearch/audiocraft) 為準。MOSNet（語音轉換 MOS，2019）見[作者程式碼](https://github.com/lochenchou/MOSNet)，只作為「學習式 MOS 預測器」這條脈絡的起點引用。PAM 的音檔、人評資料與 PAM 指標本身是不同的東西，見 [PAM 官方 repo](https://github.com/soham97/PAM)；本草稿把 PAM 當作資料集，不新增 PAM 指標欄位。

## 7. 比較協議與統計規則

MeanAudio 新的 primary 評價遵守 `evaluation_policy.md`：MusicCaps 5,521、MeanFlow 25 steps、literal CFG 3、fidelity8、generation seed 42、NoMask、full precision。完整的負向 prompt 為：`low quality recording, noisy, amateur, distorted, muffled, poor fidelity, hiss, lo-fi`。

MusicGen／MusicLDM 不能套用它們不支援的 MeanFlow solver 或 NoMask 選項，也不能給它們的輸出貼上 canonical 標籤。比較時共用文本、評價片段、聽測處理和指標實作，同時揭露各模型特有的生成差異。

### 7.1 每項測試的共同評價標準與實驗背景

同一 evaluation block 的共同設定只有一份，由各候選共同引用。正式合約記錄設定雜湊、樣本 manifest 雜湊及指標版本；下列待定值必須在正式測試前凍結，不能由各模型的腳本各自採用預設。

| 控制項 | 同一測試必須一致 | 必須登記的證據 |
|---|---|---|
| 研究問題與背景 | 同一人評目標、任務說明、音樂類型／資料來源範圍、適用人群 | 任務定義、資料來源和主要終點 |
| 輸入與抽樣 | 相同 prompt ID、逐字文本、抽樣規則、品質分層邊界；人聽使用相同子集 | 有序 ID／文本 manifest 及雜湊；重疊和抽樣紀錄 |
| 生成機會 | 每個 prompt 相同的候選數量及選擇規則：K=1，全部輸出納入 | 請求次數、seed、失敗及重試紀錄；禁止只有某模型 best-of-K 或人工挑選 |
| 調參機會 | 見第 7.5 節 | 每個候選設定的來源（官方預設或歷史選定）及選定時用過的資料與指標 |
| 評價片段 | 相同起點和時長規則、聲道處理；所有評估器評價同一段來源時窗 | 原始音檔雜湊、時窗及評價音檔雜湊；短檔不暗中補零或循環 |
| 音訊處理 | 同一 block 使用同一條 raw／響度控制／共同頻寬處理鏈、重採樣演算法和峰值規則 | 處理設定、實際 LUFS／取樣率／peak；每組都檢查 |
| 指標實作 | 比較同一指標時，各候選使用相同的權重、程式碼、精度、批次規則和聚合方法 | 評估器與環境鎖、執行紀錄；不能只對一個模型換評分器 |
| 人類評價 | 同一量尺、評分錨點、問題、播放條件、聽者資格和每項標註數 | 問卷雜湊、平衡隨機化、聽者分配與品質檢查 |
| 統計與成功標準 | 同一缺失／平手規則、信賴水準、重抽樣單位、多重比較校正和預定決策界線 | 分析設定及凍結時間；不得依某個模型的結果改門檻 |
| 分佈圖 | 同一指標使用同一 bins、軸範圍、有效值規則和正規化定義 | 作圖設定及逐 bin CSV；呈現數量和比例的分母 |

評估器可依官方介面做必要的內部重採樣或編碼；同一指標對所有候選必須使用相同的介面設定。不同指標可以有各自的介面，但不能讓 AES 評前 10 秒、MEva 評完整音檔，再把兩者當作同音檔同時窗的效度比較。

生成 seed 列表及重試政策對所有系統預先固定；同一個 seed 數字不代表不同架構產生同一個隨機實現。跨架構實驗回答的是「凍結設定下的系統輸出表現」，不能解釋成純架構的因果差異。若要比較等計算預算下的表現，必須另行登記共同預算和調參次數，不能從現有主表推論。

### 7.2 各測試允許改變的因素

| 測試 | 固定的實驗背景及標準 | 允許變化的因素 | 可支持的結論 |
|---|---|---|---|
| MeanAudio 基線 vs 目標版本 | 同文本、生成 seed、canonical 推論設定、評價 block、聽測設計 | 預先指定的 checkpoint／方法差異 | 該方法在此協議下的表現；訓練條件差異須揭露；AES 欄依 † 規則只作描述 |
| MeanAudio vs 外部模型 | 同文本、生成機會、評價片段、各指標實作、聽測標準 | 系統，及第 7.5 節登記的設定 | 「各系統推薦設定」下的系統比較；需同時報 MeanAudio CFG0 列 |
| AES vs MEva 效度 | 同一批音檔、來源時窗、人類標籤、配對、品質層和統計標準 | 評估器 | 同目標同資料範圍的效度差異；各資料集分別下結論 |
| 品質範圍測試 | 同資料來源設計、分層規則及標註目標；層內比較共用樣本 | 預登記的人類品質層 | 該範圍內的評價能力；跨層差異需考慮範圍縮窄與人類一致性 |
| SNR 階梯 | 同一基礎音檔、16 kHz、時窗、噪音類型／實現、評價處理和指標 | 噪音幅度／SNR | 對指定噪音程度的敏感度 |
| SNR 30 盲聽 | 同一音檔的原版與派生版、播放標準及相同的聽測任務 | 是否加入 SNR 30 噪音 | 可辨識性和偏好分別下結論 |
| 分數分佈 | 同評價 block、指標、覆蓋規則、bins 和軸；配對模型共用 ID | 模型或預登記處理條件 | 分佈差異；不能只憑波峰高低證明品質優劣 |

白噪音、低通、削波等不同劣化各自定義測試，不把多個同時改變的因素寫成單因素實驗。真實錄音和生成音檔按來源分層，不能把來源差異解釋成 SNR 的效果。技術品質與整體喜好雖可用同一音檔，卻是不同的評價目標，分別分析。

### 7.3 公平性及可靠性檢查

正式運行前產生 `fair_comparison_report.json`，逐項記錄上述共同設定、預期差異、核驗值和 pass／fail／invalid 狀態，**另含第 7.6 節的評分器偏誤標記表**；它須綁定批准的合約和輸入雜湊。目前這份文件只是規劃，尚未產生通過的報告。

- 任一候選有未登記的文本、時窗、處理、評分器或聽測差異，直接比較的 gate 判為 invalid。暫停該比較，記錄具體原因與下一個安全動作；不把它當作已通過公平性檢查的排名發布。
- 既有結果只有在共同評價條件及雜湊可驗證時才能複用。不相容的快取獨立標為 historical／descriptive；若要統一重評，須另立合約並保留原始結果。
- 音檔輸入和評估器 adapter 的 fixture 檢查涵蓋全部候選；重複評分的抽樣在看到分數前固定，使用共同的數值容差。不能只驗證 MeanAudio 的評分路徑。
- 科學評價條件一致，不要求同時運行或佔用相同 GPU；執行環境鎖定並記錄硬體。必須更換硬體／環境時，先驗證已登記的數值容差，不能把執行差異混進方法效果。
- 缺檔、短檔、無效評分和聽者品質失敗，對所有系統套用相同規則，並報告各系統的失效率。任何排除造成的比較集合變化依凍結規則處理；不能只刪掉某個系統的差樣本。
- preflight 檢查凍結的設定和資源；postflight 再核對實際輸入、處理和執行紀錄。資源與通知 gate 照現有 HARN 執行，不因某項科學比較 invalid 而終止仍有其他合格任務的整條佇列。

### 7.4 統計約定

- **主要人類終點**（已決定，見第 9 節）：MeanAudio 基線 CFG3+fidelity8 對 MusicGen-medium 的整體喜好 A/B 勝率（允許平手）。其他比較列為次要。

- 人類重複標註的推論須處理 prompt 和聽者的重複測量，使用預登記的混合模型或多層 bootstrap。報告平手率和有效配對的分母；模型平手、真人平手的規則預先凍結。

### 7.5 調參機會的對等（審閱新增）

### 7.7 響度規則（審閱新增，2026-10-07）

AES 不是增益不變的評分器（GroupNorm eps；063／065），PQ 越小聲越高（頂點約 −21 dB）、CLAP 越大聲越高。所以沒有「中性」的響度，只能選一個目標讓所有候選一致。各來源的自然響度並不相同（MusicCaps 原音 −18.6、MeanAudio CFG0 −18.7、CFG3+neg −20.6 LUFS；MusicGen／MusicLDM 待 P0 實測），raw 比較會把響度差混進品質差。

| block | 目標 | 角色 |
|---|---|---|
| lvl30 | −30 LUFS（ITU-R BS.1770 積分響度），純量增益 | **主要的客觀比較 block，也是聽測播放檔** |
| raw | 不處理 | 描述：系統實際輸出的響度與分數 |
| lvl23 | −23 LUFS，純量增益 | 敏感度分析：檢查排名是否依賴響度目標 |

- **為什麼是 −30 而不是 −23**：只用純量增益時，目標越高就越容易有片段的峰值超過滿刻度，必須削峰或 limiting，而 limiter 本身就會扣 PQ（064／072／074：GR 3 dB 就可測）。動態較大的系統會更常被處理，這等於只對某些候選加了處理。−30 留了足夠的餘裕，幾乎不必碰峰值；而且與 081／084／AES 稽核／Codex ablation 的 lvl30 數字直接可比。
- **峰值規則**：增益後峰值超過 0.999 時的處置（目前沿用 stage2 的 peak cap）在合約凍結；**每個系統報告觸發次數與比例**。任一系統在 lvl30 觸發率 > 1% 時，該 block 的 AES 比較標記為「處理不對等」。lvl23 預期觸發較多，也分系統報告。
- **近靜音片段**（2026-10-08 依煙測修訂）：靜音判定沿用 `eval_metrics.py`，即 raw RMS < −45 dBFS；積分響度低於 −70 LUFS（gate 失效）也算。這類片段不放大，以 raw 音訊留在比較裡，**算作該系統的失敗，不排除**。排除會獎勵輸出靜音的系統。每個系統報告靜音率；敏感度分析另報「去掉任一系統靜音的 prompt 聯集」後的結果。
  - 煙測實例：MusicGen-medium 對 `a male voice is singing a melody…`（純人聲 prompt）三個 seed 都輸出 −63～−69 LUFS，top_k 50 與 250 結果相同，是模型行為不是設定問題。MeanAudio 在人聲-only prompt 也有靜音模式（slot0nm），兩邊用同一規則計。
- **數值格式**：增益後存 float32 WAV。16-bit 在 −30 LUFS 仍安全（065：PCM_16 損傷 PQ 從 −42 dB 起），但聽測網頁若需壓縮格式，編碼器與位元率對所有候選相同並登記。
- **聽測播放**：檔案一律 −30 LUFS；音量由聽者在開始前用一段固定的校準片段調到舒適的音量，之後鎖定不改。數位位準只決定音量旋鈕的位置，人聽到的絕對響度由校準決定。聽者聽的檔案與主要客觀 block 逐位元相同，表 C（指標 vs 人類）才是同一份音訊的比較。
- **讀數限制**：lvl30 的 AES 絕對值比自然響度高約 0.1～0.27 PQ（AES 稽核第 4 節），不可與 raw 數字或外部論文混比。

## 8. 時間、儲存與運行方式

本輪未實測各模型吞吐量，暫不承諾完成天數。P1 完成後提供可執行的估算：

- 生成 GPU 工時 = 各系統樣本數 × 實測生成秒／首 ÷ 3,600；評分依評估器分別估算，另加模型載入、I/O 和重試上限。
- 聽測工時 = 單檔評分次數 × 實測秒／次 + 配對判斷與 ABX 的獨立耗時；多人平行可縮短日曆時間，但不減少總人時。
- PCM 淨資料 bytes = 音檔數 × 秒數 × 取樣率 × 聲道數 × bytes／sample。示例：5,521 首、10 秒、單聲道 16 kHz、float32 約 3.3 GiB／列；MusicGen 原生 32 kHz 加倍。外部模型原生格式、控制版本、快取與暫存會增加用量，這不是運行總預算。
- 每個可寫入的檔案系統分別計算峰值新增 bytes、暫存複本、快取、指標、日誌、checkpoint 及恢復空間，並即時量測可用空間；硬停止閾值遵守現行儲存政策。

正式長時間運行前，必須先有批准的機器可讀合約和 harn-schema-v1 bundle，綁定輸入／程式碼／權重雜湊、完整指令、階段輸出、pass／fail／invalid 分支、恢復規則與資源歸屬。評估表的完成以核驗過的產物及 terminal evidence 為準。

新的 canonical 輸出使用當前使用者獨佔的 mode-0700 run root。逐曲評分綁定 clip ID、原始和評價音檔雜湊、協議、評估器雜湊與處理規則。保留 canonical 必需的全部五個有限指標；擴充指標和圖表所需的產物也依新合約保存。在所有已登記的結果、報告與雜湊綁定完成之前不得清理。

controller 保持佇列連續運行；科學依賴與排序依賴分開登記；失敗、資源等待、通知失敗與下一任務的 hold 都持久化。start、gate、terminal、handoff、hold 等依政策使用冪等的 Discord 通知；健康輪詢不呼叫模型。本草稿不改變既有的監控或通知設定。
