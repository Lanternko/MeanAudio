# 195 AES CE 弱點：音符密度、分軌比例、配方攻擊、黑箱搜尋（預登錄，2026-11-13）

狀態：設計登錄；p2 195，eval-only，約 3–4 h，分 stage 可續跑。上游：`docs/experiments/muq_ce_cmi_next_stage_20261111.md` §191（Part A 人類殘差已做：`ce_human_residual_20261111_results.md`；CE 痛點翻分數：`ce_painpoint_mining_20261111_results.md`）。
授權：使用者 2026-11-13「go」。AES 只評分，不訓練；無人類評分，結果只描述評分器方向。

## 0. 要回答的問題

既有證據：CE 在 MIDI 上「多 30% 音符」+0.15～+0.17、全部錯音 +0.07～+0.12（123）；拿掉 MUSDB 伴奏 +0.16（126c）；生成音樂殘差偏好貝斯／打擊／高頻（191 A）；190 個合成刺激 CE 最高 5.23（真實第 27 百分位）。
1. **Part B**：CE 隨音符密度怎麼長？是「和聲內加音」還是「任何加音」都加分？有沒有飽和點？
2. **Part C**：單一分軌加減 dB，CE 的曲面長怎樣？哪個分軌是槓桿？
3. **Part D**：把 B／C 的發現做成一行可解釋的後製（分軌重混、疊調內琶音），能不能在生成音檔上把 CE 推高、且比對照多？
4. **Part E**：黑箱合成搜尋能不能找到 CE 高過真實音樂中位數的簡單聲音？

## 1. Part B：MIDI 音符密度階梯

- 素材：123 的 150 段 MAESTRO 摘錄（`~/eval_output_nvme/midi_realpiece_123/excerpts.json`）× 2 SoundFont（generaluser、fluidr3），沿用 123 的 `synth`／`render_excerpt`，16 kHz、10 s、−30 LUFS。
- 格（16）：`base`；`extra_harm_{10,30,60,100}`（新加音的音高從該段自身的 pitch-class 分布抽、落在原音域內，和聲內加音）；`extra_rand_{10,30,60,100}`（123 的 `extra`，隨機音高）；`wrong_{10,30,60,100}`（±1／±2 半音）；`vel_rand`；`jitter_20ms`、`jitter_50ms`。百分比＝相對原音符數。每段每格 rng 種子 = hash(段 id, 格, 20261113)。
- 評分：AES 四軸（CE 為主）、MuQ A1／A3a、PAM、CMI-RM empty。
- 讀數：每格 ΔCE（對 `base`，段 bootstrap 5,000，以演奏為 cluster）；劑量曲線；飽和點＝最小達到該族最大 ΔCE 90% 的劑量。**判定**：`extra_harm_30` 的 ΔCE 與 123 的 +0.15～+0.17 同號且 CI 下界 > 0 → 複製成立；`extra_harm_X − extra_rand_X` 在 30／60／100 三檔中 ≥ 2 檔 CI 下界 > 0 → 「CE 偏好和聲內加音」，≥ 2 檔 CI 上界 < 0 →「偏好不和諧加音」，其餘「不分和聲」。

## 2. Part C：分軌增益曲面（一次一軸）

- 素材：126c 的 MUSDB 窗快取（`~/eval_output_nvme/metric_win_tie_126c_20261019/stimuli/cache/`，約 550 窗 × 4 分軌），10 s、16 kHz。
- 格（29）：`base`；每個分軌（vocals／drums／bass／other）× {−12, −6, −3, +3, +6, +12 dB, 移除}。重混後整段鎖 −30 LUFS。
- 分析只用該分軌有聲的窗（126c 的活動門檻）；曲目為 cluster bootstrap。
- 評分：AES 四軸、MuQ A1、PAM、CMI-RM empty。
- 讀數：每分軌的 ΔCE 曲線；**排出 ΔCE 最大的三個（分軌, dB）格**，作 Part D 的重混配方（只用 Part C 選，與 D 的 MusicCaps 底不重疊，無偷看）。

## 3. Part D：配方攻擊（9 個 MusicCaps 底）

- 底：9 個 MusicCaps 底（同 189），`load_base`。dev 200 id／test 800 id 沿用 193 的切分。
- 候選：
  - `mix*`：htdemucs（190 F5 的分離）拆四軌，套 Part C 前三名（分軌, dB）中的一個或組合（共 4 個候選：前三名各自＋三者合併），重混、鎖 −30 LUFS。對照 `mix_ctrl`：同一分軌套相反的 dB。
  - `arp*`：估底的調性（librosa chroma ＋ Krumhansl 剖面；偏差 D1），疊主和弦琶音（根–三–五–八度，每音 0.25 s，123 `synth` 的 generaluser 鋼琴），音量低於底 12 或 18 LU（2 個候選）。對照 `arp_ctrl`：同一琶音移三全音（離調）。
- **挑選**：在 6 個能聽的底（真實、CFG3＋neg × 3、MusicGen、MusicLDM）的 dev 200 id 合併上，各族挑 ΔCE（對 base）最大的候選 → `mix*`、`arp*`，凍結在 `selection.json` 後才評 test。
- **test**：800 id × 9 底，格 `base`、`mix*`、`mix_ctrl`、`arp*`、`arp_ctrl`。
- **成功（每底）**：ΔCE(配方 − base) CI 下界 > m_CE（0.119 = 0.10 × S_CE 1.190）**且** ΔCE(配方 − 對照) CI 下界 > 0。
- **主判定（6 個能聽的底成功數）**：≥ 5 成立、2–4 依底而定、≤ 1 不成立；MUSDB 不跑（Part C 已是 MUSDB）。
- 守門讀數（描述）：MuQ A1、PAM、CMI-RM caption、AES PQ；CE 升而 PAM／CMI-RM 降 → 記為「只有 CE 看得到的加分」。

## 4. Part E：CE 黑箱合成搜尋

- 合成器：約 20 個參數（波形混合 sine／saw／square、和弦型、八度、音符長度與 ADSR、節奏密度、頻譜 tilt、低通截止、鼓層（kick／snare／hat 程式化）音量、動態），10 s、16 kHz、−30 LUFS。
- 搜尋：numpy 對角 ES（cma 未安裝；偏差 D2），3 次重啟、合計 20,000 次 AES 評估，目標＝CE。
- 凍結前 10 名，跑全部評分器（AES 四軸、MuQ A1／A3a、PAM、CMI-RM empty、CLAP 對 "music"），並報其 CE 在真實 MusicCaps 1,000 段 CE 分布的百分位。
- **判定**：前 10 名任一 CE > 真實中位數 → 「存在高 CE 簡單聲音」；否則「找不到」（先驗：188 最高 5.23 ＝ 第 27 百分位）。

## 5. 偏差（預先寫明）

- D1：調性估計用 librosa chroma＋Krumhansl，不用 madmom key_cnn（另一個 venv）。
- D2：Part E 用 numpy ES，不用 CMA-ES 套件。
- D3：pulse_clarity／key_cnn_conf 不進守門讀數（另一個 venv）。
- D4：Part E 的搜尋目標是 CE 本身，屬於對 CE 的黑箱最佳化；只用來回答「存在與否」，不當攻擊配方，也不在 MusicCaps 底上使用。

- D5（實作審查時補）：Part C 的 `base` 是四軌直接相加，不是原混音檔（讓所有格同一來源）；「移除」的對照方向用 +12 dB。
- D6：Part C 活動窗門檻由實作定：該軌 LUFS ≥ −45 且 ≥ 混音 −20 LU、活動比例 ≥ 0.6。
- D7：Part D 的 htdemucs 分軌以 float16 暫存；Part E 的鋸齒波／方波是 naive 波形（有混疊）。
- D8：Part E 的「真實中位數」＝ Part D 真實 MusicCaps 底 dev＋test 1,000 段的 `base` CE。
