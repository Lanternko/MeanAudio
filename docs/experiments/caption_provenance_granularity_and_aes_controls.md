# Caption provenance、音訊粒度與 AES 控制實驗

本文件是 Phase 7/8 與 `caption10s` 實驗的名詞基準。若其他文件使用
`official Qwen`、`30s caption`、`segment` 或 `clip` 而未明確定義，應以本文件為準。

## 1. 「official」不代表人工官方標註

歷史檔名 `phase8_qwen_official_matched*` 中的 `official` 只表示 caption JSON
由上游 `ICME26-ATTM-GC-FluxAudio` reference repository 隨程式提供。上游 README
稱其為 "official captions generated by Qwen"。它不是 MTG-Jamendo 的人工
ground truth，也不是本專案自行逐段產生的官方標註。

為避免歧義，正文統一使用以下名稱：

- **LP-MC segment caption**：由既有 LP-MusicCaps 結果取得，索引鍵包含
  `segment_N`；每個約 30 秒的本地 segment 有自己的候選 captions，Phase 7
  從五個候選中選一筆。
- **upstream track-level Qwen caption**：上游
  `data/captions/jamendo_qwen.json` 的 Qwen 產物；每列路徑是
  `{prefix}/{track_id}.mp3`，沒有 `segment_N`。
- **local 10s Qwen caption**：本專案後來針對每個本地 segment 的前 10 秒
  重新產生的 onesent 或 multisent caption。

`official Qwen` 只保留在不可任意改名的歷史檔案、實驗 ID 與路徑中；敘述來源時
不得把它簡寫成「官方標註」。

## 2. Track、segment 與實際訓練 window

資料有三層，不應都稱為 clip：

1. **Track**：一首完整歌曲。
2. **Local segment**：`segments_no_vocals/{prefix}/{track}/segment_N.mp3`，
   實際抽查長度約 `30.0408 s`。
3. **Training window**：目前 251,599-row 訓練 manifest 對每個 local segment
   只使用 suffix `_0` 的窗口，也就是 segment 的前 `160,000` samples at
   16 kHz（名義 10.000 秒）；NPZ latent 為 312 frames，對應約 9.975 秒。

因此，模型實際看到的音訊不是整首歌，也不是完整 30 秒 segment，而是每個被選中
segment 的**前 10 秒**。新版 local 10s Qwen caption 也讀取同一段前 10 秒音訊。

### 一首歌會有幾個 segment？

不能只由歌曲長度武斷地回答。若 210 秒歌曲被完整、連續且不重疊地每 30 秒切分，
直觀上會有約 7 段；但目前 repository 沒有保存建立
`segments_no_vocals/segment_N.mp3` 的原始 full-track-to-segment 切分程式與完整
provenance，因此不能由現有證據保證邊界、尾段、重疊或過濾規則。

目前可由訓練 TSV 直接驗證的是：

| 項目 | 數值 |
|---|---:|
| 訓練 rows / local segments | 251,599 |
| unique tracks | 36,985 |
| 每 track 保留 segments 平均數 | 6.80 |
| 中位數 | 6 |
| 範圍 | 1–109 |

這些是「最後保留在訓練 manifest 的數量」，不是完整歌曲切分規則。個別歌曲可能有
segment 被篩除；不可把 `歌曲秒數 / 30` 當成每首歌必然的訓練 row 數。

`training/partition_clips.py` 是下一層的 10 秒窗口切分器：一般情況會在一個輸入
音檔內最多取 5 個均勻分布的 10 秒窗口。但目前這份 251,599-row manifest 的 ID
全部以 `_0` 結尾，實際只訓練每個約 30 秒 local segment 的第一個 10 秒窗口。

## 3. Caption 到底如何共用？

| Caption source | Caption 索引粒度 | 同一 track 的 N 個 retained segments | 每個訓練 row 的對齊 |
|---|---|---|---|
| LP-MC segment caption | local `segment_N` | 通常有 N 筆各自不同的 caption | 30s segment caption 配該 segment 的 first-10s window；仍有 30s→10s mismatch |
| upstream track-level Qwen | track | **一筆 caption 展開成 N 筆** | track ID 正確，但未使用 `segment_N`，是 track→10s mismatch |
| local 10s Qwen | local `segment_N` 的 first 10s | N 個窗口各自 caption | 10s→10s，粒度一致 |

舊 mapper `scripts/preprocess/phase8_qwen_official_mapper.py` 只從本地 ID 解析
`(prefix, track)`，再查上游 `{prefix}/{track}.mp3`。所以它不是把 A 歌配成 B 歌，
而是把同一首歌的一筆 upstream track-level caption 廣播到該歌所有 retained
segments。若某 track 有 7 個 retained segments，同一 caption 就會出現在 7 個
訓練 rows；全 corpus 平均約重複 6.80 rows/track。

這是時間粒度不合，不是 LP-MC 的行為。LP-MC caption 的鍵包含 `segment_N`，同一首
歌不同 segments 可有不同描述。

## 4. AES 下跌：需要分離的兩個因果問題

「caption 品質」至少混合了兩件事：

- **時間對齊品質**：caption 是否描述實際送入模型的那 10 秒。
- **描述風格／廣度**：在對齊正確時，是否涵蓋 arrangement、production、mix、
  recording fidelity 等可能與 Audiobox Aesthetics 有關的資訊。

只比較 upstream track-level Qwen 與 local 10s Qwen，兩項因素同時改變，不能把
AES 差異單獨歸因於 caption 內容較短、較差或不夠廣。

## 5. 已排程的 R-Shared 控制組

目前要回答的問題不是「任意錯配 caption 會不會傷害模型」，而是重現舊式
track-level supervision：同一首歌的所有 retained 10 秒 segments 共用一筆 rich caption。
因此已放棄 R-Permuted，改用以下直接控制：

| Arm | 實際訓練 segment | Caption 綁定 | 規模 |
|---|---:|---|---:|
| R-Matched | 每列前 10 秒 | 每個 segment 自己的 rich caption | 既有 quarter 基準 |
| R-Shared | 每列前 10 秒 | 同 track 所有列共用一個同歌 rich caption | 新跑 quarter |

R-Shared 保留完整 251,599 列、36,985 tracks、原 row order 與 audio latent；每首歌以
固定 seed 42 的 SHA-256 選擇一個 retained segment 作 caption source，再 broadcast 到該
track 的所有列。這避免永遠挑第一段造成的位置偏差。36,985 個 source rows 保持原 caption，
其餘列改用同歌 source caption；平均一筆 source caption 對應約 6.80 個訓練 rows。

這不是只改 alignment 的純控制：它有意同時重現 track-level caption 的重複率與較粗時間
粒度。因此它能直接回答「舊式同歌共用 supervision 是否解釋 AES/CLAP 差異」，但不能單獨
把效果拆成 alignment 與文字分布兩個機制。

### 訓練與升級門檻

- R-Shared 使用與既有 R-Matched quarter 相同的 251,599 rows、NoQ、seed 14159265、
  batch 8、learning rate 1e-4、S1 100k + S2 50k。
- 兩者皆以 MusicCaps 5,521、generation seed 42、MeanFlow 1 step、CFG 0.5 評估；
  CLAP 是 primary semantic endpoint，CE 是 primary AES endpoint。
- `R-Matched - R-Shared` 必須滿足 CLAP `>= +0.005`，且 CE `>= -0.06`，才自動啟動
  R-Matched full scale（S1 400k + S2 200k）。PQ/CU/PC 仍完整報告，但不作事後挑選門檻。
- 缺少 corpus/NPZ 綁定稽核、checkpoint 或任何非有限 metric 都視為技術失敗並停止。
  R-Shared 分數低但完整有效，則是「共享 caption 有害」的實驗結果，不會被當成技術
  collapse 而否決 promotion。

## 6. 目前證據能說到哪裡

現有 onesent vs multisent quarter 已做到相同 10s audio、ID set、captioner、訓練參數
與 eval；multisent 相對 onesent 的 CE `+0.1926`、CLAP `+0.0182`，但 CU/PC/PQ
只有 `+0.035–0.051`，落在該實驗事前定義的 null band。這支持「production-aware
多句描述可能改善 CE」，不等於 AES 全面改善，也尚未排除單一 training seed 的變異。

因此下一步先做上面的單一 R-Shared quarter 控制；若通過預註冊門檻，就把資源集中到
R-Matched full-scale confirmation。這輪是一個 seed 的決策實驗，結論應解讀為資源升級
依據，而不是跨 seed 的最終統計證明。
