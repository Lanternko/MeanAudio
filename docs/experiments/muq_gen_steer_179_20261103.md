# 179：生成端能不能把 MuQ 偏誤頻段（4–8 kHz）推下去、刷高 MuQ

設計登錄：2026-11-03，**評分前登錄**。GPU 任務：p2 179。

## 0. 為什麼做

`results/muq_attack_fix_20261103_results.md` 的結論：MuQ-Eval A1 MI 在真實錄音上**越窄越好**——低通 4–6 kHz 一律加分（MUSDB +0.38～+0.46、ODAQ reference +0.40～+0.43），人類 MUSHRA 卻是低通越深越低。降到 16 kHz 之後 8 kHz 以上已經沒有內容，但 **4–8 kHz 本身還有 +0.14～+0.16**（ODAQ reference，F1）的偏誤。

那份結果全部是**後處理**（對既有音檔做 lowpass）。這次問的是生成端：**不做任何後處理**，只靠 prompt 或推論期引導向量，能不能壓低 4–8 kHz 能量，並因此把 MuQ 拉高？

用途：如果成立，這就是「拿 MuQ 當 reward 會被 hack」的生成端證據——最佳化器不需要真的改進音質，只要學會把 4–8 kHz 壓下去就能漲分。如果不成立，則與 D1（缺陷 prompt 推不進參考臂定義的缺陷區）同類：文字推不動這個頻段，下一步才值得花成本做梯度引導。

## 1. 刺激

- **checkpoint**：114，`~/exps_nvme/phase8_qwen_caption2p0_slot0clean_nmv2matched_noq_full_s14159265_stage2_200000/phase8_qwen_caption2p0_slot0clean_nmv2matched_noq_full_s14159265_stage2_200000_ema_final.pth`。NoQ（`--no_q`）、NoMask（`--no_text_attention_mask`）。
- **prompt**：`/mnt/HDD/kojiek/phase4_jamendo_data/musiccaps_test.tsv` 的**前 1000 筆 csv record**。切片按 csv record（`csv.DictReader`），不用 `head`——該 TSV 有 5 條 caption 在引號內跨行。切片檔 `inputs/mc1000.tsv` 保留原 header 與原 caption 文字。
- **生成設定**：MeanFlow 25 步、seed 42、fp32、`--variant meanaudio_s`、`--use_meanflow`、`--encoder_name t5_clap`、`--text_c_dim 512`，其餘旗標與 `scripts/eval/mc_mf25_eval.sh` 的 cfg3neg 格完全相同。
- **fidelity8**（A0 的負向）＝`low quality recording, noisy, amateur, distorted, muffled, poor fidelity, hiss, lo-fi`（直接取自 `mc_mf25_eval.sh` 的 `NEG`）。

## 2. arm（全部 cfg 3.0）

| arm | 實作 | 正向 | 負向 |
|---|---|---|---|
| **A0** | vanilla | caption | fidelity8 |
| **A1** | vanilla | caption | `bright, crisp, sparkling treble, airy high frequencies` |
| **A2** | vanilla | caption | fidelity8 + `, bright, crisp, sparkling treble, airy high frequencies` |
| **A3** | vanilla（`--prompt_suffix`） | caption + `, warm, dark, muffled sound` | fidelity8 |
| **A4** | 組合式引導向量 λ=1 | 見下 | fidelity8 |
| **A5** | 組合式引導向量 λ=2 | 見下 | fidelity8 |

A4／A5 的推論期組合：

```
u = u(neg) + 3·(u(c) − u(neg)) + λ·(u(c_dark) − u(c_bright))
c_dark   = caption + ", warm, dark, muffled sound"
c_bright = caption + ", bright, crisp, sparkling treble"
neg      = fidelity8
```

λ=0 時化簡為 `u(neg) + 3·(u(c) − u(neg))`，與 A0 的 vanilla CFG 代數等價（浮點運算順序不同）。

實作方式：`runpy` 跑原 `eval.py`，在 `meanaudio.eval_utils.generate_mf` 上 monkeypatch 一個支援四個條件分支的版本。**不改** `meanaudio/model/networks.py`、`eval.py`、`mc_mf25_eval.sh`。A0–A3 走完全不 patch 的 vanilla 路徑。

**λ=0 一致性檢查**：另跑 `A4_L0`（同一個 patched 路徑、λ=0）4 段，與 A0 前 4 段逐樣本比較，記最大絕對差。只作為 harness 驗證，不進 arm 家族、不進任何判準。

## 3. 評分（每個 arm、每個 clip）

- **操弄檢查**（不用 GPU）：
  - `band_ratio_db`：16 kHz 音訊、Hann 窗 n_fft=1024／hop=512 的平均功率譜，`10·log10(Σ_{4k≤f<8k} P / Σ_{0≤f<8k} P)`。
  - `centroid_hz`：同一平均功率譜在 0–8 kHz 的頻譜重心。
- **MuQ-Eval**：A1 MI／TA、A3a MI／TA。走 `scripts/eval/muq_attack_fix_20261103.py` 的 F0 路徑（identity，不做輸入修補；16 kHz 輸入原樣送 `score_muqeval`）。
- **AES**：PQ／CE／CU／PC（`eval_metrics.score_aes`，batch 32）。
- **CLAP**：逐檔 batch 1（`eval_metrics.score_clap`），文字端一律原始 caption。
- **level**：LUFS、靜音（RMS < −45 dBFS）數量（`eval_metrics.score_level`）。
- **後處理參考曲線**（不用 GPU 生成）：對 A0 音檔做 lowpass 4k／5k／6k（沿用 `scripts/eval/muq_lowpass_probe_20261028.py` 的 `lp`，8 階 Butterworth、sosfiltfilt），只算 MuQ A1／A3a 與 band 特徵，用來得到「後處理攻擊」的 (Δ頻段, ΔMuQ) 曲線。這些音檔不落地。
- **統計**：所有 arm 都與 A0 **以 prompt 配對**（同一 clip id）比較；bootstrap 2000 次、seed 0，報平均差的 95% CI。CLAP／AES／MuQ 都是逐 clip 配對。

## 4. 預登錄判準

### 操弄成立（manipulation）

arm 的 `band_ratio_db` 比 A0 低 **≥ 3 dB**，且配對差的 bootstrap **CI 上界 < 0**。

### 生成端攻擊成立（generation-side attack）

同時滿足：

1. 該 arm 的操弄成立；
2. MuQ **A1 MI** 的 Δ ≥ **+0.10**，且 bootstrap **CI 下界 > 0**；
3. AES **PQ** 的 Δ ≤ 0（點估計），且 CI 上界 < **+0.05**。

任一 arm 達成即算成立，報告要寫明是哪一個。多個 arm 達成時，以主要家族 **A1–A5** 做 Holm 校正並另外報出來。

- Holm 的檢定量：MuQ A1 MI Δ 的**單尾** bootstrap p 值（H0: Δ ≤ 0；p = 2000 次重抽樣中平均 ≤ 0 的比例），家族 = A1–A5 五個 arm。操弄與 PQ 條件仍照上面各自檢查，Holm 只校正 MuQ 這一項。校正後 p < 0.05 記為「Holm 後仍顯著」。

### 機制檢查（描述性，不進判準）

把各 arm 的 (Δ`band_ratio_db`, ΔMuQ A1 MI) 畫在後處理 lowpass 4k／5k／6k 曲線旁邊，判斷生成端的加分是否「走同一條線」——即同樣的 ΔdB 是否換到同樣的 ΔMuQ。同時報 Δ`centroid_hz`。

### 操弄全部不成立時

結論寫「文字推不動頻段（同 D1）」，並建議下一步改用 mel 域的梯度引導。**不得**把「操弄不成立」寫成「生成端不能被 hack」。

## 5. 預期（評分前寫下）

- A1／A2（負向加 bright）大概只動 < 1.5 dB：負向槽的領域文字在 084／107 顯示會影響 PQ，但沒有證據能移動頻譜。
- A3（正向加 dark）可能比 A1／A2 大（1–2 dB），因為它改的是 content 條件本身；但 T5 是 mean-pool，長尾綴會被稀釋。
- A4／A5 是唯一有機會到 2–4 dB 的 arm，因為差值向量是逐 step 直接加在速度場上。
- MuQ 要 +0.10 大概需要 ≥ 3 dB 的頻段移動（後處理曲線 lp4k 約 +0.38、lp6k +0.46，但 16 kHz 素材上 4–8 kHz 的量化幅度較小）。
- 因此最可能的結局是「操弄不成立、攻擊不成立」，這次變成 D1 的頻譜版本。

## 6. 時間與執行

- **預估**：6 個 arm × 1000 段生成（A4／A5 每步 4 次 forward，約 2× 成本）≈ 20 分；MuQ 評分（6000 arm 段 × 2 variant＋3000 lowpass 段 × 2）≈ 20 分；AES＋CLAP＋level ≈ 8 分；分析與寫檔 < 5 分。**GPU 總計約 1–1.5 h**，走 p2 queue（> 30 min）。
- **smoke**：GPU 空閒時直接跑，每個 arm `--limit 4`（另加 A4_L0 一致性檢查），掛 notify trap；smoke 輸出在 `_smoke/`，正式 job 不讀。
- **輸出**：`~/nvme_experiment_artifacts/meanaudio/muq_gen_steer_179/`。
- **結果檔**：`docs/experiments/results/muq_gen_steer_179_results.md`、`docs/experiments/results/muq_gen_steer_179_summary.json`，由 job 跑完後的分析步驟產生，結果 md 用三段式（`# 總評`、`**關鍵數據與例子**`、`**要你決定的事**`）。

## 7. 不可寫

- 不可寫成「MuQ-Eval 可以被 reward hack」的普遍結論：這裡只有**一個 checkpoint（114）、一個 seed、前 1000 個 MusicCaps prompt、16 kHz 輸出**，而且只動 4–8 kHz。
- 後處理 lowpass 曲線是**後處理**，不是生成端的能力；兩者只能拿來做機制對照。
- 沒有任何本次刺激的人類評分；「人類分數會掉」是借用 `muq_attack_fix_20261103` 的 ODAQ MUSHRA 錨點，不是這次量的。
- 操弄不成立 ≠ 生成端不可能被 hack；只等於「這幾種文字／差值向量推不動」。
- A4／A5 的 λ 只有 1 與 2 兩點，不能畫出完整的劑量反應曲線。
