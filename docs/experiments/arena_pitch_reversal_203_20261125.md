# 203 移調／變速在 Music Arena 反向的原因（2026-11-25 預登錄）

問題來源：`results/arena_consequence_200_results.md` 結論 3。移調 −2 半音、變速 0.9x 在 197 的 16 kHz 生成底上讓 MuQ A1 上升（+0.222／+0.065），在 Arena 音檔上下降（−0.092／−0.113）。

eval-only，只評 MuQ A1／A3a。不重訓、不碰評分器。**無人類評分。**

## 1. 已經知道的事（200 既有逐段分數，登錄前就看過）

| 切法 | 移調 −2 ΔA1 | 變速 0.9x ΔA1 |
|---|---|---|
| Arena 32 kHz（MusicGen small／medium，433 段） | −0.030 | −0.015 |
| Arena 44.1 kHz（2,535 段） | −0.120 | −0.148 |
| Arena 48 kHz（1,030 段） | −0.049 | −0.069 |
| 197 MusicGen 底（16 kHz） | +0.226 | +0.038 |
| 197 MeanAudio 六個底（16 kHz） | +0.265～+0.330 | +0.092～+0.143 |
| 197 真實錄音底（16 kHz） | +0.060 | −0.016 |

- Arena 15 個系統兩種處理全部為負，沒有任何系統是正的 → 不是少數系統拉低平均。
- 同一個模型家族（MusicGen）在 Arena 32 kHz 是 −0.03，在 197 的 16 kHz 是 +0.226。兩邊的差別是取樣率（頻寬），prompt 與模型大小也不同。
- 逐段 Δ 與低通 6 kHz 的 Δ 正相關（r 0.32／0.26）；與未處理的 A1 負相關（−0.34／−0.37）。

以上是登錄前看到的，只當動機，不當檢定。

## 2. 假說

**H1（偽裝的低通）**：16 kHz 音檔的內容上限是 8 kHz。往下移 2 個半音後，內容上限變成 8000 × 2^(−2/12) ≈ 7,127 Hz，7.1～8 kHz 變空。MuQ A1 本來就獎勵低通（193：7 kHz +0.103、6 kHz +0.154），所以分數上升的來源是頂端頻段被清空，不是音高。寬頻音檔往下移時，8 kHz 以上的內容會補進來，頂端不會變空，只剩 rubberband 與音高本身的代價。

**H2（變速）**：變速不改變頻譜上限，H1 不直接解釋它。候選：rubberband 在 16 kHz 下的時間伸縮本身讓高頻變少（視窗短、暫態被抹平）。沒有方向性預測，只做描述。

## 3. 刺激

Arena 3,998 段中每個系統取 50 段（不足取全部），固定 seed 20261125，約 748 段。載入、中心 30 秒、單聲道、響度鎖回原值，全部沿用 `scripts/eval/arena_consequence_200.py` 的函式（import，不改該檔）。

| 條件 | 做法 |
|---|---|
| `d16_F0` | 原生取樣率 → soxr HQ 降到 16 kHz |
| `d16_rb_id` | 在 16 kHz 上 rubberband 原速原調 |
| `d16_ps_m2` | 在 16 kHz 上移調 −2 半音（等同 197 的做法） |
| `d16_ts_090` | 在 16 kHz 上變速 0.9x |
| `d16_lp7127` | 在 16 kHz 上只做 7,127 Hz 低通（8 階 Butterworth 零相位，與 193／200 同一個 `lp`），不移調 |
| `ps_m2_to16` | 原生取樣率移調 −2（8 kHz 以上的內容補下來），再降到 16 kHz |
| `ts_090_to16` | 原生取樣率變速 0.9x，再降到 16 kHz |

原生取樣率的 `F0`／`ps_m2`／`ts_090`／`rb_id` 直接讀 200 的逐段分數（同一批 id）。

拆解（都對 `d16_F0`）：

- 總效果 T = `d16_ps_m2` − `d16_F0`
- 音高＋處理（頂端頻段不空）P = `ps_m2_to16` − `d16_F0`
- 頂端清空 E = `d16_ps_m2` − `ps_m2_to16`
- 純低通 L = `d16_lp7127` − `d16_F0`

## 4. 判準（主端點：MuQ A1 MI，m = 0.055，bootstrap 5,000 次、以段為單位）

| 判定 | 條件 |
|---|---|
| **H1 成立** | T 的 CI 下界 > 0（Arena 音檔降到 16 kHz 後方向翻回正的），且 E 的 CI 下界 > 0 |
| H1 部分成立 | E 的 CI 下界 > 0，但 T 的 CI 跨零或為負（清空頂端有加分，但蓋不過音高代價） |
| H1 不成立 | E 的 CI 上界 ≤ 0，或 T 的 CI 上界 < 0 且 E 跨零 |

附帶讀數（不進判定）：L 是否 > 0 且與 E 同量級；T 是否 ≥ m；逐系統 T 為正的系統數；`d16_F0` − 原生 `F0`（降取樣本身的效果，180 已知為正）。

變速（描述）：`d16_ts_090` − `d16_F0` 與 `ts_090_to16` − `d16_F0` 各自的符號與 CI。兩者都負 → 197 的 +0.065 是 197 那批底的特性，與取樣率無關；前者正後者負 → 是 16 kHz 下 rubberband 的行為。

## 5. 範圍與限制

- 只回答「為什麼方向不同」，不改 197／200 的任何判定。
- 降到 16 kHz 的 Arena 音檔仍是商用系統的輸出，不等於 197 的 MeanAudio／MusicLDM 底；H1 成立只說明頻寬是原因之一。197 真實錄音底在 16 kHz 下也只有 +0.060，表示素材本身也有影響，這裡不拆。
- 子集約 748 段，不重算一致率與排名。
