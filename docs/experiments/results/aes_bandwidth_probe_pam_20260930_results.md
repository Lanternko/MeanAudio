# AES 16 kHz 偏誤是頻寬造成的嗎？PAM 低通 probe（2026-09-30）

接續 `aes_human_corr_pam_20260929_results.md`。那份的觀察是：AES 把兩個 16 kHz 擴散系統（audioldm2、musicldm）的 PQ 比人類高估 1.2～1.5 分。當時推論的原因是 AES 先重取樣到 16 kHz，所以看不到 8 kHz 以上的頻段；而人類聽得到寬頻系統的高頻，會給它們加分。這份 probe 把這個推論拆成兩部分來檢查。

## 方法

- **A. 前提**：把寬頻片段（musicgen_large、musicgen_melody、real，各 100 首）用 FFT 硬截斷低通到 8 kHz，存成 float wav 後重新跑 AES。如果 AES 真的看不到 8 kHz 以上，分數差應該接近 0。
- **B. 人類端**：每首片段算 HF share（8 kHz 以上能量佔總能量的比例），殘差定義為 residual = 人類平均 − AES raw。如果人類會獎勵 AES 看不到的高頻，那麼在寬頻系統**內部**，殘差應該隨 log10 HF share 上升。分兩種算法：
  - 系統內去平均後合併（n = 300）
  - 各系統分開算
  - 信賴區間用 bootstrap 2000 次
- 腳本：`research/eval/aes_bandwidth_probe_pam.py`；輸出：`research/eval/output/aes_bandwidth_probe_pam/`。GPU 約 1 分鐘，屬於直接跑的短 probe。

## 結果

### A. 前提成立：低通後 AES 幾乎不變

| 系統 | PQ 平均 Δ | PQ 平均 \|Δ\| | 最大 \|Δ\| |
|---|---|---|---|
| musicgen_large | −0.016 | 0.037 | 0.26 |
| musicgen_melody | −0.022 | 0.036 | 0.26 |
| real | −0.019 | 0.038 | 0.43 |

- 其他三軸的平均 Δ 都在 ±0.02 以內。
- 每首片段的 |Δ| 大約 0.03，比重跑 batch 的雜訊（~1e-3）大。原因可能是 FFT 硬截斷在 8 kHz 附近引起的振鈴，或是 16 kHz 重取樣時抗混疊濾波器過渡帶的差異。
- 這些差異的量級遠小於 1.2～1.5 的系統高估。所以 **AES 看不到 8 kHz 以上** 這一點得到確認。

HF share 中位數：

| 系統 | HF share 中位數 |
|---|---|
| audioldm2、musicldm | 0（完全沒有高頻） |
| musicgen_large | 0.0014 |
| musicgen_melody | 0.0007 |
| real | 0.0022 |

### B. 人類端的預測沒有得到支持

| 軸 | 系統內去平均合併 r(殘差, HF) [95% CI] | musicgen_large | musicgen_melody | real |
|---|---|---|---|---|
| PQ | −0.096 [−0.217, +0.034] | +0.080 | +0.049 | **−0.342** |
| PC | −0.163 [−0.279, −0.037] | −0.144 | −0.116 | −0.224 |
| CE | −0.171 [−0.276, −0.061] | −0.142 | −0.082 | −0.257 |
| CU | −0.220 [−0.345, −0.090] | −0.145 | −0.189 | −0.295 |

- 人類分數確實跟 HF share 正相關：musicgen 的 PQ r 是 +0.38～+0.49。
- 但 AES 跟 HF share 的相關差不多大，甚至更大：合併的 PQ 是 +0.34 對人類的 +0.31，PC 是 +0.56 對 +0.48。AES 自己看不到高頻，所以它是透過跟高頻共變的其他特徵（整體製作品質）得到這個相關。
- 因此在系統內部，殘差沒有隨高頻上升：
  - PQ 的 CI 跨零。
  - 其他三軸都顯著為**負**。
  - real 系統的 PQ 是 −0.34。

## 判讀

1. **「AES 看不到 8 kHz 以上」是事實，但無法用系統內部的高頻差異解釋 16 kHz 系統被高估。** 寬頻系統內部，高頻多一點或少一點，AES 都沒有「少給分」。
2. **這不等於否證頻寬解釋。** 寬頻系統的系統內差異，跟 audioldm2／musicldm「完全沒有高頻」（HF share = 0）不是同一種情況。人類對「整段沒有高頻、聽起來悶」的反應，可能是門檻式的，不是線性的；這份資料測不到這種效應。
3. **要真正回答這個問題，需要人類聽過低通版本並評分**（例如把 musicgen 低通到 8 kHz 後做成對試聽）。這需要新的聽測。
4. 另一個同樣符合資料的解釋：16 kHz 擴散系統的高估，來自 AES 看不出擴散模型或 vocoder 的特有瑕疵（例如 phasiness、偏平的瞬態），跟頻寬無關。PAM 資料無法把這兩種解釋分開。

## 對既有結論的影響

- 「我們的 AES 分數不可跟 32k／44.1k 外部模型比」這條結論**不變**。16 kHz 系統被高估是觀察到的現象，這份 probe 只是讓「原因是頻寬」這個解釋降級成未證實。
- MeanAudio 同時具備兩個條件：輸出 16 kHz，而且是 latent 擴散／flow 模型加 vocoder。所以兩種解釋對我們都成立，實務上的結論不受影響。
