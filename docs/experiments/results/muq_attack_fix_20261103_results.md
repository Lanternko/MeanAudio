- **F1 不成立**：它消除的是「MUSDB 上的 8–12 kHz 偏袒」，不是低通攻擊本身；ODAQ reference 的 4–8 kHz 移除仍穩定加分（+0.14～+0.16，17/30 上升）。以預登錄語言記為「只消除了部分跨頻寬偏袒，沒有讓指標學會低通是劣化」。
- **F2 依預登錄規則三條全過**，但通過的形式是「把評分器看不到的頻帶一起砍掉」：4 kHz 以上一律抹平，所以它不可能再獎勵低通；判準 2 的相關幾乎只由 LP35 與 LP50 的殘餘差異撐起。這不是「學會低通是劣化」，而是「把偏誤所在的頻段遮住」。**不建議**當成 TTM 比較的 drop-in 修補（會喪失所有 4 kHz 以上的判別力）；它的價值是定位出偏誤頻段。

## 判讀

1. **低通偏誤的頻段被定位得更清楚**：F1（只砍 8 kHz 以上）把 MUSDB 的 lp4–6k 從 +0.4 翻成 −0.1，但 ODAQref 還有 +0.14～+0.16；F2（砍 4 kHz 以上）才讓兩組都翻負。也就是說 MuQ-Eval A1 的「越窄越好」不是單一 8–12 kHz 現象，4–8 kHz 在真實錄音上也有同方向（只是幅度較小、且在不同素材組不一致）。
2. **預登錄判準下 F2 是唯一三條全過（A1 MI）的修補，但它是遮蔽而不是學習**：4 kHz 以上全部抹平後，低通不可能再加分；人類錨點的相關只剩 LP35／LP50 的殘差在撐，且那些殘差 < 0.001 相對 RMS 就能造成 0.1–0.45 的分數差——反過來證明 A1 在截止頻率邊緣極度敏感。若要把 MuQ 用在跨系統比較，**不建議**套 F2 當修補；Part B 的結果顯示這次的 TTM 比較不需要它。
3. **TTM 表可以用 MuQ-Eval 讀，但只在這批素材上**：musicgen 32k→16k 對 A1 MI 的平均影響是 0，六個系統排名不動，與 cfg3_neg 的成對差在 F0／F1 都是 +0.188。這與 AES 在 PAM 上高估 16 kHz 系統的已知問題**不同**；原因是 musicgen 的 >8 kHz 能量比真實錄音低 6–10 dB（事後檢查），不是 MuQ 對取樣率穩健的普遍證明。
4. **候選 3／4／5 都是小效果**：dither 近乎無效、gain 平均不變（單段可動 2 分）、htdemucs 重組近平手。MuQ-Eval 的弱點集中在「真實錄音的 4 kHz 以上內容」這一條，不在靜音底噪或響度。

## 限制

- **ODAQ LP 只有 4 個 trial**，pooled Spearman 沒有 CI；F2 的 0.400 幾乎由 LP35 與 LP50 兩個條件決定。F2 下其餘條件彼此訊號差 < 0.001 相對 RMS，分數差是數值殘差造成的，不能解讀成「F2 學會了排序」。
- **mc522 與 MusicEval 都是窄頻／in-domain**：mc522 是 16 kHz 真實錄音，MusicEval 是 MuQ-Eval 的訓練來源（只用 dev＋test）；兩者的「效度沒掉」不代表在寬頻生成音訊上的效度。
- **Part B 只抽 1,000 個 prompt**（共同檔名 5,131 個，seed 0）；單段在 32k→16k 下最大可動 0.97，所以逐段結論不穩，只有平均／成對差可用。
- 126c stems 快取只覆蓋 145／150 首、551 個 11 s 窗，且是 16 kHz mono；未覆蓋的 5 首沒跑（dac venv 沒有 demucs）。分離重組的 Δ 不能直接與 Part A 的寬頻 Δ 比大小。
- 沒有任何本次刺激的人類評分；人類方向借用 ODAQ 官方 MUSHRA（LP 系列）與 mc522／MusicEval 的既有評分。
- Part C 的 dither 只在 20 ms 幀、RMS < −50 dBFS 的條件下加；沒有掃「整段加微量雜訊」的對照。
