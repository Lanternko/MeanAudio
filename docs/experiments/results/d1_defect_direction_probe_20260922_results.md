# D1：模型有沒有「缺陷方向」？（defect-direction probe）

2026-09-22 跑，2026-09-23 判讀。checkpoint `phase8_qwen_caption10s_multisent_noq_full_stage2_200000`
（c2p0_slot0 full NoQ，與 073／negprompt 消融同一顆），`--no_q`，MeanFlow 25 步 / seed 42 /
fp32 / NoMask，兩格皆**不帶負向 prompt**：cfg0 與 cfg3 null-neg。14 條 prompt × 128 樣本 = 1,792/格。

原始表：`~/eval_output_nvme/d1_analysis.md`。產物：`d1_noise_probe_{cfg0,cfg3}/`、
`d1_degrade_reference/`。腳本：`scripts/eval/d1_{noise_probe_tsv,degrade_reference,analyze}.py`、
`scripts/eval/run_d1_noise_probe.sh`。

## 問的是什麼

031 的定論是 negprompt 增益來自 fidelity 領域詞彙、不是缺陷極性。一個從未檢定的解釋是：
**模型根本沒有缺陷方向**，因為訓練語料裡沒有壞音訊被標成壞。QA-MDT 用一句沒有實驗的話
講過同一件事（「low quality 的 text embedding 在訓練期大概沒被 disentangle」，見
`docs/literature/negative_samples_in_training_and_cfg_2026_09_22.md`）。D1 量它。

## 參考臂先確認「量得到」

把 clean 生成的 clip 程式化劣化、每片重新對回原片 integrated LUFS 後評分（paired，vs 各自來源）：

| 劣化 | CLAP | PQ | CE |
|---|---|---|---|
| noise_snr0 | **−0.1587 ±0.0118** | −2.3386 | −3.0044 |
| noise_snr10 | −0.1055 | −1.3726 | −1.2971 |
| noise_snr20 | −0.0636 | −0.6993 | −0.5575 |
| clip_18db | −0.0158 | **−2.4731** | −2.9598 |
| lowpass_1k | −0.0610 | −0.9236 | −1.3431 |
| bitcrush_4 | −0.0181 | −1.2048 | −1.7025 |

→ 指標對真實劣化有反應，而且**方向可逆**：同一批噪音 clip 改用缺陷 caption 評，
noise_snr0 的 CLAP 從 0.0739 翻到 **0.1943**。所以「CLAP 讀不讀得出是雜訊」這件事本身成立，
「defect prompt 沒動」不能用「指標量不到」解釋。**這組座標就是缺陷區的位置。**

## 主結果一：prompt 裡有音樂時，缺陷詞推不進缺陷區

rock stem 為基線（cfg3 格，cfg0 同向較弱）：

| prompt | CLAP | PQ | CE |
|---|---|---|---|
| axis/noisy | +0.0051 ns | −0.7384 | −0.8617 |
| axis/distorted | +0.0228 | −0.6030 | −0.6290 |
| axis/lofi | +0.0256 | −0.1764 | −0.2373 |
| axis/muffled | +0.0498 | +0.0561 ns | −0.0867 |
| full/rock（整串缺陷詞） | +0.0135 | −0.4913 | −0.5336 |

- PQ 確實掉，但只有真實劣化的 1/3～1/5（−0.49 vs −1.4～−2.5）。
- CLAP 對自身 prompt 略升（+0.005～+0.050）。**但這不能當作「有沒有進缺陷區」的判準** ——
  見下方「主結果三」：CLAP 的缺陷 caption 分數會被「安靜／空」刷上去，純數位靜音的得分
  高過真的被削波、被低通的音訊。跨 group 的 CLAP 在這裡只能當描述，不能當方向判準。
- 可用的判準是**波形簽名**（見主結果三的表）：真加噪 crest 升、真削波 crest 崩，
  而 prompt 兩者都做不出來。這與 031 的「領域詞彙不是缺陷極性」一致。
- 響度不是解釋：這些 group 的 LUFS 差在 ±0.9 dB 內。

## 主結果二：prompt 裡沒有音樂時，模型是「安靜下來」不是「變壞」

pure 組（純缺陷、無音樂）確實大幅離開 clean 區，但去的方向不對：

| cfg3 | CLAP(自身 prompt) | PQ | CE | PC | LUFS | 靜音比 |
|---|---|---|---|---|---|---|
| clean/rock | 0.1854 | 6.7392 | 7.2055 | 6.1661 | −13.0 | 0.00 |
| pure/white | 0.2690 | 5.9590 | 3.5096 | 2.1705 | **−55.1** | **0.80** |
| pure/static | 0.2249 | 5.4426 | 3.0037 | 2.1859 | −34.3 | 0.16 |
| ref/noise_snr0（真噪音，缺陷 caption） | 0.1943 | 4.7960 | 4.3028 | 4.6162 | −16.1 | 0.00 |

- 「做白噪音」→ 平均 −55 LUFS、80% clip 判為靜音、peak 0.026。模型的逃逸方式是**輸出幾乎沒有東西**。
- 真噪音的座標是 PQ 4.80 / CE 4.30 / PC 4.62、響度正常；生成的 pure 組是 PC ≈2.2、CE ≈3.0，
  落在完全不同的角落。**不是同一個區域。**
- ⚠️ pure 組的 AES 數字帶大幅響度位移（−34～−55 LUFS），063/065 的響度效應一定有污染。
  → 已補響度對齊重評（見「主結果四」）：**AES 的差距在固定響度下存活，「靜音」則大半是響度**。

## 主結果三：波形簽名對不上，而 CLAP 的缺陷分數被靜音刷掉

### (a) 缺陷詞壓出來的不是被點名的缺陷

cfg3，rock stem ＋ 單一缺陷軸 vs 乾淨 rock；對照欄是程式化劣化（paired，LUFS 已鎖）：

| | crest | peak |
|---|---|---|
| `noisy` prompt | −0.101 ±0.107 **ns** | −0.017 ±0.007 |
| 真加噪 SNR 10 dB | **+0.186** ±0.041 | −0.009 ±0.006 |
| 真加噪 SNR 0 dB | **+0.155** ±0.107 | −0.156 ±0.012 |
| `distorted` prompt | −0.195 ±0.114 | −0.007 ±0.006 |
| 真削波 +6 dB | **−2.377** ±0.096 | −0.414 ±0.007 |
| 真削波 +18 dB | **−3.699** ±0.167 | −0.645 ±0.011 |
| `muffled` prompt（PC −0.11） | +0.246 ±0.103 | −0.002 **ns** |
| 真低通 2 kHz（PC −0.50）／1 kHz（PC −0.90） | +0.114／+0.066 | +0.029／+0.026 |

真加噪讓 crest **升**、真削波讓 crest **崩**，缺陷詞兩者都做不出來。
→ 缺陷詞觸發的是**籠統的「把音樂做差」方向**，不是被點名的聲學缺陷。

### (b) CLAP 在 caption 固定時測得到缺陷⋯⋯

配對比較（同一條缺陷 caption，劣化音訊 vs 它自己的未劣化原片，n=192。
未劣化那側是把原片以相同 id 命名後重評，所以「換 caption」與「換音訊」被拆開）：

| 真劣化 | ΔCLAP |
|---|---|
| noise SNR 0 / 10 / 20 | +0.2647 ±0.0084 / +0.2366 / +0.1083 |
| clip +18 dB / +6 dB | +0.1419 ±0.0056 / +0.0141 |
| lowpass 1k / 2k | +0.1216 ±0.0057 / +0.0681 |
| bitcrush 4-bit / 8-bit | +0.0595 ±0.0101 / +0.0433 |

九項 CI 全不跨零且**隨劑量單調**。CLAP 對缺陷不是瞎的。

### (c) ⋯⋯但它的缺陷分數被「小聲／空」污染到不能用

同一條 caption、三種音訊來源（cfg3）：

| 缺陷 caption | 乾淨音樂 | **真的劣化** | **模型被要求做出該缺陷** |
|---|---|---|---|
| static noise and tape hiss, no music | −0.0704 | +0.1943 | **+0.2249** |
| harsh digital distortion and clipping, no music | −0.1452 | −0.0034 | **+0.2493** |
| a muffled low-bitrate recording…, no music | −0.0611 | +0.0606 | **+0.2941** |

模型的產出在三條 caption 上都「贏過」真的有那個缺陷的音訊。把音量單獨拉出來看
（乾淨 rock 音樂逐級衰減，n=64）：

| 音量 | static | clipping | muffled |
|---|---|---|---|
| 原音量 | −0.0549 | −0.1230 | −0.0755 |
| −30 dB | +0.0075 | −0.1013 | +0.0690 |
| −48 dB | +0.0419 | −0.0787 | +0.1170 |
| **數位靜音** | **+0.1162** | **+0.1284** | **+0.1687** |

**純數位靜音的缺陷 caption 得分，高過真被削波（−0.003）與真被低通（+0.061）的音訊**；
真 0 dB SNR 雜訊（+0.194）比靜音（+0.116）也只高 0.078。
→ **CLAP 不可當缺陷驗收指標。** D2（訓練期標壞資料）的驗收軸目前只有 AES 的 PQ/CE 可用
（對真劣化單調、對 level 的方向已知）；**PC 對加噪／bitcrush 反而上升，不可用**。

### (d) 「做白噪音」做出來的不是白噪音

| | 頻譜平坦度 | RMS |
|---|---|---|
| 真·白雜訊（數學對照） | **0.5607** | — |
| `white noise` cfg3 | 0.0383 | −61.4 dBFS |
| `white noise` cfg0 | 0.0351 | −48.4 dBFS |
| 乾淨 rock stem cfg3 | 0.0204 | −13.0 dBFS |

平坦度只從 0.020 爬到 0.038（離真雜訊 0.56 差一個數量級），振幅卻掉 48 dB。
逃逸是**振幅塌陷**，與 slot0nm 的稀疏 prompt 靜音模式同型。

## 主結果四：全部對齊到 −30 LUFS 後重評

2026-09-23 補跑。純量增益逐片對到 −30 LUFS：1,779/1,792 乾淨對齊，6 個 peak capped、
7 個數位靜音無有限響度（後兩類分開列，不混進平均）。目標先試 −14 失敗——1,096/1,792 會削頂
（clean 組原本 peak 就 0.93）；−30 兩個方向都有餘裕。表：`~/eval_output_nvme/d1_analysis_levelmatched.md`。

cfg3，vs 同樣在 −30 LUFS 的 clean/rock：

| group | CLAP | PQ | CE | PC | 靜音比 |
|---|---|---|---|---|---|
| axis/noisy | −0.0350 | −0.6559 | −0.8039 | −0.2865 | 0.00 |
| axis/distorted | −0.0357 | −0.5426 | −0.5743 | −0.1584 | 0.00 |
| full/rock | −0.0588 | −0.4103 | −0.4108 | −0.3179 | 0.00 |
| pure/static | +0.0725 | −1.4210 | −3.9956 | −3.8595 | +0.016 |
| pure/white | +0.0520 | −1.5726 | −3.7960 | −3.5481 | +0.102 |
| pure/clip | +0.1086 | −1.4755 | −4.3762 | −4.0260 | +0.086 |

1. **pure 組的 AES 崩塌不是響度假象**：固定響度後 PQ 仍 −1.1～−1.6、CE −3.8～−4.4、
   PC −3.5～−4.0。振幅塌陷之外確實有內容上的差別。
2. **但「靜音」大半是響度**：pure/white 靜音比 0.80→0.10、pure/static 0.16→0.016，
   全樣本只剩 7 個 clip 真的沒有有限響度。準確說法是「把能量壓到很低」，不是「輸出數位靜音」——
   與主結果三 (d) 的振幅塌陷同一件事。
3. **axis 組 CLAP 的正負號不耐響度操作點**：原生 +0.005～+0.050、−30 LUFS 下 −0.035～−0.059，
   兩邊幅度都小。這是主結果一「CLAP 不可當方向判準」的獨立佐證，理由不同（那裡是靜音刷分，
   這裡是操作點）。

⚠️ 這格在 −30 LUFS、參考臂在各自來源的 ~−16 LUFS，**操作點不同，絕對 AES 不可跨兩組比**；
可比的是各自 vs 自己 clean 基線的 delta。

## 結論

1. **這顆模型沒有可用的、文字可達的、逐項的缺陷方向。** 它有兩樣東西：
   (a) 一個籠統的「把音樂做差」方向，量級不到真劣化的一半且波形簽名對不上；
   (b) 一個完全 OOD 時的振幅塌陷逃生口。
2. 因此 QA-MDT 那句沒有實驗的猜測，在我們這顆 checkpoint 上**量到了、方向一致**。
3. 推論：負向 prompt 這條線的上界被訓練分布釘死——負向分支指得到的區域，模型沒有建模過。
   要再往前，應該改成 F4（把負向分支從一段文字換成一個模型：autoguidance / NPO）或
   F2（訓練期把壞資料標起來），見 `docs/literature/negative_samples_in_training_and_cfg_2026_09_22.md`。
4. **這不是「模型不能生成壞音訊」的證明**——只證明 T5 文字條件推不到。也沒有跨 checkpoint
   驗證（只有一顆 NoQ 模型、一個 stem 集合、每 prompt 128 樣本）。

## 限制

- CLAP 在各 group 是對各自的 prompt 算的，跨 group 的絕對值不可直接比；可比的是參考臂的
  paired delta，以及主結果三 (c) 那三條「prompt 文字與參考 caption 逐字相同」的行。
  「換 caption 是否翻轉」**已被證明不是有效判準**（靜音就能製造翻轉）。
- 主結果三 (c) 只涵蓋三條逐字相同的 caption；`white noise` 沒有對應的劣化參考，未進該表。
- AES 官方實作截到 16 kHz，bitcrush 的高頻 aliasing 有一部分在評分器視線外。
- 生成端原生格未鎖響度（參考臂有鎖）；已補 −30 LUFS 對齊格（主結果四），但它與參考臂操作點不同。
- 單 checkpoint、單 seed（eval seed 42）。訓練 seed 雜訊底線未套用。
