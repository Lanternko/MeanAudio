# MIR 指標對 AES 的增量效度結果（MusicEval，2026-09-30）

設計與預登錄門檻：`../mir_incremental_validity_musiceval_20260930.md`。
輸出：`research/eval/output/musiceval_mir/summary.{txt,json}`、`per_clip_musiceval.tsv`。
資料：MusicEval（HF `BAAI/MusicEval`；baseline repo https://github.com/NKU-HLT/MusicEval-baseline；AudioMOS 2025 Track 1），2,748 首，主分析集是 shared 2,500 首（25 系統 × 100 prompt）。

## 一句話

**預登錄門檻全過**：MIR 特徵在 AES 之外能多解釋人類 OVL，配對勝負也多對 2～3 個百分點，留一系統時一樣成立。但兩點要一起寫：(1) 增量大半來自**系統之間**的差異，同一系統內只有調性類特徵（key 信心、chroma 熵）還剩訊號，拍點類特徵在系統內 CI 都跨零；(2) 把 AES 換成非線性模型（HGB）後，prompt CV 的增量從 +0.088 縮到 +0.021，剛好壓在 0.02 門檻上。

## 增量效度（OVL）

ΔR²、Δpair 為 F−B，CI 為 bootstrap 2,000 次（prompt CV 對 prompt 抽；LOSO 對系統抽）。

| CV | 模型 | R²(B) | R²(F) | ΔR² [CI] | Δpair(all) [CI] | sys ρ B→F |
|---|---|---|---|---|---|---|
| prompt 10 折 | ridge（**主**） | 0.547 | 0.635 | **+0.088** [+0.073, +0.104] | +0.022 [+0.016, +0.028] | 0.913→0.945 |
| prompt 10 折 | HGB | 0.667 | 0.689 | +0.021 [+0.010, +0.034] | +0.007 [+0.002, +0.012] | 0.964→0.975 |
| 留一系統 | ridge（**主**） | 0.461 | 0.564 | **+0.103** [+0.057, +0.164] | +0.028 [+0.021, +0.033] | 0.903→0.911（Δ CI [−0.019, +0.042]） |
| 留一系統 | HGB | 0.592 | 0.656 | +0.064 [+0.033, +0.103] | +0.021 [+0.016, +0.027] | 0.908→0.939 |

只有 MIR＋干擾共變量（M）：prompt ridge R² 0.547，跟只用 AES 的 B 一樣。

**門檻判讀**
1. prompt CV ΔR² ≥ 0.02 且 CI > 0：**過**（+0.088）
2. 配對一致率 Δ CI > 0：**過**（+0.022；三個 \|Δ\| 分組也都 > 0）
3. 留一系統 ΔR² CI > 0 且系統 Spearman 不降：**過**（+0.103；Spearman +0.008，但 CI 跨零）

→ 依預登錄寫「MIR 有增量效度、可用於比較模型」。

**要一起報的限制**
- **系統層級排名其實沒變好**：LOSO ridge 的系統 Spearman 只 +0.008 且 CI 跨零；門檻寫的是「不降」所以算過，但不能說 MIR 改善了系統排名。
- **線性 AES 吃虧**：HGB 只用 AES＋干擾就到 R² 0.667，比 ridge 的 F（0.635）還高。ridge 的 +0.088 有一部分是 MIR 在補 AES 的非線性。HGB 上 prompt CV 增量 +0.021 剛好過 0.02、配對只 +0.007；LOSO 上 HGB 仍有 +0.064，比較站得住。
- **系統之間 vs 系統之內**：逐特徵系統內偏相關只有調性類站得住（見上）；增量主要是「新系統的拍子／調性整體清不清楚」。對同一架構內的 arm 差異（我們的使用情境，差異小得多）能不能分辨，這份資料沒回答。
- **REL（文字符合度）**：prompt CV +0.021 [+0.010, +0.031]，LOSO +0.014 跨零、系統 Spearman −0.035 → MIR 對 REL 不泛化，符合預期（MIR 不看文字）。

- 在另一批生成音樂（不同系統、不同評分者、5 s 片段）上方向複製、大小相近 → 不是 MusicEval 專屬。
- **真實錄音上拍點特徵對 PQ 幾乎沒訊號**：真實音樂拍子本來就穩，這些特徵抓的是「生成音樂的節奏崩壞」，不是一般的製作品質。
- 標 `*` 的（danceability、部分 tempo_drift、key_stability）在外部集不穩，不引用。

## 探索：MusicCaps 1,000 prompt，真實錄音 vs nmv2 arm（只描述，不當證據）

| | 真實 | nmv2 CFG0 | nmv2 CFG3+neg |
|---|---|---|---|
| AES PQ（勝真實比例） | 6.93 | 6.51（0.31） | **7.34（0.60）** |
| AES CE | 6.20 | 6.16（0.50） | **6.85（0.73）** |
| CLAP | 0.304 | 0.203 | 0.227 |
| pulse_clarity | 0.613 | 0.379（**0.18**） | 0.401（**0.19**） |
| ibi_cv（越低越穩） | 0.030 | 0.047（0.81） | 0.050（0.83） |
| tempo_drift | 0.022 | 0.042（0.70） | 0.043（0.70） |
| key_stability | 0.667 | 0.612 | 0.616 |
| key_cnn_conf | 0.616 | 0.578 | 0.634 |
| chroma_entropy（越低越好） | 0.903 | 0.929 | 0.912 |

（括號是「arm 值 > 真實」的 prompt 比例；ibi_cv／tempo_drift 越高代表越常比真實不穩。）

- AES 說 CFG3+neg 在 60%（PQ）／73%（CE）的 prompt 勝過真實錄音；**拍點清晰度只在 19% 的 prompt 勝過真實**，拍間距在 83% 的 prompt 比真實不穩。負向 prompt 把 AES 推高，但 pulse_clarity 只從 0.379 → 0.401，差距幾乎沒收。
- 調性類在 CFG3+neg 上跟真實接近（key_cnn_conf 0.634 vs 0.616）。
- danceability CFG3+neg 大幅升（1.58 vs 1.28），但它在 MusicEval 沒有效度，不解讀。
- 這跟試聽「CFG3+neg 不如真實錄音」的印象方向一致，但 MusicCaps 片段 10 s、沒有人類分數，只能當假說：**AES 超車真實錄音的部分，節奏清晰度沒有跟上。**

## 能寫／不能寫

- 能寫：在 MusicEval（25 系統、專家 OVL）上，12 個 MIR 特徵加進 AES 後 out-of-fold R² +0.09（prompt CV）／+0.10（留一系統），配對勝負 +2～3 點；方向在 PAM 生成音樂上複製。
- 能寫：拍點類特徵的訊號在系統之間，系統內跨零；系統內剩下的是調性清晰度。
- 不能寫：「MIR 改善模型排名」（系統 Spearman Δ CI 跨零）。
- 不能寫：「MIR 能分辨同架構 arm 的細微差異」（沒測）。
- 不能寫：探索段的 arm 比較是證據（無人類分數、未預登錄）。
