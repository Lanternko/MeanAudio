## 對「生成 PQ 為何高過原音」的含義

只寫到「支持／削弱」這一層，見 memory 中的三欄分類。

1. **PQ ≈ 8.2–8.3 不是生成器才拿得到的分數。** 乾淨合成 MIDI（8.26）與 karaoke-jp 的真實歌曲（8.20）在 −23 LUFS 下都在這一帶，都高於 Jamendo 語料（7.55）和 MusicCaps 原音（6.90）。這**支持**稽核的判讀：「超車」主要是相對於業餘、現場、帶噪的參考集。這**削弱**「8.2 一定是指標被 game 才拿得到」的說法；但 081 超過**它自己的訓練語料**這一點仍然成立，見 `aes_gen_exceeds_ref_audit_20260930_results.md`。
   - 注意：這兩個數字是在 −23 LUFS；081 的 8.20 是在 lvl30（−30 LUFS）。依 063／065，−30 LUFS 的 PQ 會比 −23 LUFS 略高，所以不能逐位比。
2. **寬頻噪聲是最強、最一致的槓桿**：兩種素材都呈劑量反應。如果生成器（透過 negprompt 或 PQ 標籤）學會產出比語料更少噪聲的音訊，PQ 上升的方向與這裡一致。但本輪沒有直接測生成音訊：NegMF 轉移支線因為音訊缺失沒有跑。
3. **「更稀疏、更安靜的背景 = 更高 PQ」不成立。** 去鼓、去人聲、去伴奏、壓低安靜段都扣分；唯一的例外是移除 pad（PQ +0.065，同時 CE −0.16）。
4. **PQ 幾乎看不到音樂結構。** pitch shuffle、和弦重排都在 ±0.05 內；10 秒區塊重排完全不變（AES 是 10 秒窗平均）。這和 MIR 增量效度那條線的結論相容：系統內只剩調性類訊號。
5. **音色與音域效應中等（±0.1～0.5），且依 SoundFont 翻轉**，不能當成普遍的樂器偏好。
