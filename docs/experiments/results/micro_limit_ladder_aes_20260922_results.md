## 代價是連續爬出零的，不是跳階

072 只能說「GR 8.4 dB 時代價已是飽和值的 31%」，看起來像有跳階。補上這六階之後形狀清楚了：

| GR 區間 | 邊際代價 |
|---|---:|
| 3.15 → 4.56 dB | −0.0256 PQ/dB |
| 4.56 → 5.70 | −0.0364 |
| 5.70 → 6.68 | −0.0443 |
| 6.68 → 7.58 | −0.0499 |
| 7.58 → 8.40 | −0.0530 |

**每 dB GR 的邊際代價在淺端最小，隨 GR 遞增**（3.15→8.40 dB 之間翻一倍）。
接上 072／065 之後整條代價曲線是 **S 形**：淺端上凸（離開零時平緩）、中段最陡、
GR 25 dB 後飽和（94%）、GR 43 dB 完全飽和。佔飽和值比例：D0.5 3.5%、D1 8.3%、
D1.5 13.6%、D2 19.3%、D2.5 25.1%、D3 30.8%。

所以現在**可以寫**「處理代價隨 GR 從零連續長出」—— 預註冊的第一條判定規則
（`cost_starts_at_zero_and_deepens_monotonically`）在形狀上成立，
只是它與第二條（D0.5 已可測）同時成立：曲線是連續的，但連續不等於有免費區間。

**仍不可寫**「GR 3.15 dB 以下沒有代價」—— 那一段一樣沒量到（見限制）。

## 曲線已接通

`z0` 是三條線共用的點（PQ 7.5992）：純量、向下 limiting、064 的向上 limiting 都從它出發。
limiter 曲線現在從 −84 dB 連續走到 0 dB，再由 064 接到 +6.8 LU，中間沒有斷點、沒有推測段。

兩側離開 z0 的斜率不對稱：往下壓 3 dB 要 8.4 dB GR、PQ 掉 0.176；往上推 2.4 LU、PQ 只掉 0.069。
**同樣是「動 limiter」，向下方向貴得多**，因為向下需要的 GR 遠大於向上。

## 判讀

1. **代價曲線在淺端是上凸的。** 「壓一點點」的邊際代價確實比「壓很多」小，
   但「一點點」的下限是 GR 3 dB，而那裡已經扣 −0.027 PQ。
2. **AES 比 CLAP 敏感一個量級。** 四個 AES 軸在 GR 3.15 dB 全部可測，CLAP 要到 4.6 dB。
   arm 之間比 PQ 前要鎖響度，這一條再度加強。
3. **PC 依然是唯一偏好 limiting 的軸**（+0.023 → +0.098，單調）。與 064／065／072 同向。
   SongEval 量到 PC 的人類相關性最低（0.408），不宜據此說 limiting 讓音樂更好。
4. **有兩個片段壓不到 0.5 dB**（原始峰值貼近 −1 dBTP）。量級可忽略，但它是「limiter 只削峰」
   這個限制的直接證據。

## 對既有結論的影響

- 072 的「輕度 limiting 無免費區間」**維持**，並下修到 GR 3 dB 的量級。
- 072 登記的「GR < 8.4 dB 未量」**已補上 3.15～8.40 dB**；未量區間縮到 GR < 3.15 dB。
- 064／065 的「不能用 limiter 修分數」不變。要對齊響度仍然只能用純量。

## 限制

單一 checkpoint、單一 generation seed（051 baseline 音檔）、單一 limiter（x42-dpl, release 50 ms）；
064b 已證明處理代價大小依 limiter 實作差 12 倍，絕對數字只對 dpl 成立。
**GR < 3.15 dB 仍未量，且這個設計造不出來** —— L\* 目標小於 0.5 dB 時，
二分搜尋的 0.05 LU 容忍度會吃掉整個訊號。要再往下必須改量測協定（收緊容忍度或直接瞄準 GR，
後者會失去等響度雙胞胎）。因此**不可**宣稱「存在免費區間」。
`summary.json` 的 `floors` 與 `shape_float` 在這個範圍沒有意義，預註冊已登記為不可讀。
AES 無響度正規化、16 kHz 截頻，絕對值不可跨論文比較。CI 跨零是證據不足不是等效。
AES 與 CLAP 都不是人類判斷。
